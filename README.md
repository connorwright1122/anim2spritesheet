# anim2spritesheet
 
A Blender addon to automate the creation of pixel art spritesheets from 3D models inspired by the process used by Motion Twin for Dead Cells. 
This also provides the ability to render normal map spritesheets for dynamic lighting of sprites in game engines. 

## How to Use
1. Install add-on
2. In Blender scene hierarchy, set primary camera that focuses on animation
3. Enter anim2spritesheet n-panel in Render tab (hit N, navigate to Render > anim2spritesheet) 
4. Set resolution and start/end frames of animation
5. Select checkboxes based on what renders you want (base, normal)
6. Choose output directory (will create subfolders based on checkboxes that overwrite previous)
7. Hit Render button

## Export safety and output
* No external Python packages or network access are required. Enabling the add-on no longer installs or upgrades anything in Blender.
* Every successful render creates a new `export-<id>` folder inside the selected directory. It contains Base/Normal/Emission frame folders for the selected maps, corresponding PNG sheets, and `manifest.json` recording source frames and sheet layout. Existing exports are retained.
* Only the explicit frames from the current run are packed. Output is PNG/RGBA/8-bit at 100% resolution with square pixels; compositing, sequencer processing, render borders, and multiview are temporarily disabled.
* A failed or canceled render discards its staging folder. Changed render settings and the current frame are restored through a cleanup guard.
* Preview renders the current frame at the export dimensions without stretching it into a square.
* The packer supports non-interlaced RGBA8 PNGs generated by the exporter and limits atlas pixel buffers to 256 MiB.

## Current limitations
* Base is the lit beauty render, not extracted unlit albedo.
* Normal still uses the original Workbench normal matcap; engine-space encoding is not yet validated.
* Emission still uses viewport rendering and requires running from a 3D viewport. It is not a headless emission pipeline.
* Exports run synchronously. A responsive job queue and modern extension packaging remain future work.
* The EEVEE identifier handles Blender 4.0/4.2–4.x/5.x differences. This does not establish full runtime compatibility: local Blender background startup crashed before verification. Windows and Linux have not been tested.

## Development checks
Run `python3 -m unittest discover -s tests -v`. These checks cover PNG filters and exact pixel packing, inconsistent dimensions, version routing, failure cleanup, source sample manifests, and state restoration using isolated stand-ins. They do not replace render tests inside Blender.
